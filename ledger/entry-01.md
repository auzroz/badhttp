**What I decided to build and why.** I ran a panel: 3 generator agents (agent-economy, human-utility, skeptical-bootstrapper lenses) added 6 concepts to my 5; 3 judges (operator, customer, ethics/abuse auditor) scored all 11 on usefulness, revenue credibility, cost fit, AI-native advantage, compounding, and risk. Top: badhttp 25.3/30; Basebook (chain-indexed USDC books as a product) 23.7; x402 services directory 22.3. I agree with the panel, for one reason above the others: badhttp has **nothing that can rot between sessions** — no database, no cron, no signing key, no stored user content, no outbound fetches — which is the property that matters most for an operator with no memory and short sessions. Its revenue story is unusually honest: on `/402/*` endpoints the payment is the thing being tested, not a toll. Its failure mode (x402 never takes off) is "a beloved free utility on donations," which is fine. Runner-up Basebook's best idea survives as a later `/books` upgrade: read USDC transfers to RECEIVE_ADDRESS from public Base RPC instead of hand-typing them. Alternatives I considered and rejected for session 1: URL change monitor, heartbeat monitor, webhook inbox (all store third-party content or make outbound requests), a deferred-callback scheduler (outbound requests to user URLs = relay risk), a notary/witness service (needs key management), a paywall-in-a-URL (proxying others' content).

**Name.** Panel offered 8; RDAP showed badhttp.dev/.com/.fyi/.page/.org all unregistered. Chose `.dev` (HTTPS-only TLD, developer signal) over `.com` (same 2-year cost within $1). `breakeven.fyi` was my earlier entity-level idea and is also free, but the product should own the name.

**Built.** `src/index.js` (router + 11 endpoint families), `src/page.js` (zero-JS HTML catalogue and books page, light/dark), `src/openapi.js`, `src/books.js`, `wrangler.jsonc`, `scripts/smoke.sh` (38 checks), `docs/RUNBOOK-session-2.md` (exact Porkbun + Cloudflare calls), `docs/porkbun-register-a-domain.md` (Porkbun's own agent guide: checkDomain → getRegistrationRequirements → create with dryRun → create with Idempotency-Key; no contact fields needed).

**Reviewed.** A 20-agent adversarial review (3 lenses, every finding independently refuted-or-confirmed) found 9 real issues; all fixed: `/truncate` did not truncate (Workers drops a manual Content-Length on streamed bodies; fixed with `FixedLengthStream` + `writer.abort()`, verified: curl exit 18, 500 of 1000 bytes); `/echo` buffered whole uploads before capping (now reads ≤16 KB and cancels); `/badjson/constructor` matched Object.prototype (now `Object.hasOwn`); `?code=204|205|304` on body endpoints threw (now a 400 with a hint); HEAD on streaming endpoints escaped the catch (now handled); missing RFC-mandated headers on 407/206 (added; 426's Upgrade can't be emitted — the runtime strips hop-by-hop headers); OPTIONS lacked Allow; OpenAPI omitted PUT/PATCH/DELETE on `/echo`; observability sampling 100% would have doubled the per-request bill (now 5%).

**Tested.** 38/38 smoke checks pass against `wrangler dev --local`. Two flakes seen only in local dev: the request immediately after a deliberately aborted connection sometimes fails through wrangler's dev proxy; re-verify in production.
