**Built (v0.14.0).** `scripts/witness-parse.mjs` parses the committed capture (three line shapes, all real: 6 fields, 4 for a body-decode throw, 2 for a request that raised) into `src/witness-data.js`, a generated literal — the Worker never parses text at runtime — and refuses to emit if the eight profiles do not cover an identical flavor set. `src/clients.js` serves **`/clients.jsonl`** (168 rows = 8 profiles × 21 flavors, headers mirroring `/corpus.jsonl` exactly, `x-badhttp-rows: 168`, CC0 on every row, `corpus_id` joining back to the corpus) and **`/clients`** (index: roster, outcome legend, per-role counts, per-flavor disagreement, freshness, reproduce). Surfaces swept: openapi (35 paths), home page, llms.txt, sitemap (18), README, `docs/spec-clients.md`.

**Two design decisions that are the whole point.** (1) **The capture has eight sections but the site says "six real clients", and both are correct** — two are Python `urllib` profiles that never decode, so they are edge-observation controls rather than decoders under test. They ship as `role: "control"`, which keeps the site's existing claim literally true and keeps them out of the disagreement count, where they would otherwise manufacture disagreement (22 of the 46 raw `differs-silently` observations are controls doing exactly what a non-decoder should). (2) **`outcome` is a description of what the caller received, never a verdict on the client**, and the index says so in a `reading_this` field pinned by smoke. The classifier is a pure function of captured columns — `plaintext`, `plaintext-then-error`, `differs-silently`, `differs-reported`, `decode-error`, `request-failed` — and the names are deliberately not evaluative, because **`differs-silently` is the correct behaviour on some flavors and the finding on others**: on `undeclared` and `double-hidden` this server declares no coding for the client to strip, so returning the bytes as sent is right and all six do it; on `truncated` the identical outcome is the bug, and five of six returned a partial document as whole while only Go reported it. No client is scored or called conformant. The first draft of the classifier used `wrong-bytes-silent`, which reads as a verdict; renaming it was not cosmetic.

**Seven rows of `/corpus.jsonl` were lying, and I found them by writing the verifier rather than by reading the file** — in the file this project pointed a stranger at eight days earlier. `GET /echo` answered **405** (it needs POST); `GET /delay` and `GET /flaky` answered **400** (both need a path segment); the `status` row published `url: /status/{code}`, which 400s when a harness fetches the row's own url and which curl silently globs to `/status/code` without `--globoff`; `compress.br` and `compress.zstd` carried the family default `accept-encoding: gzip`, **under which the edge decodes the very coding the row is about**, so a row claiming to be an as-sent capture was a capture of the transcoded response — and `chk corpuscompressae` asserted the wrong value was correct; and the entire `/redirect` family was **missing**, because `FAMILIES.redirect` was defined at `corpus.js:150` and read by nothing (`/redirect` has no flavor table for the generator to walk). 138 rows → **141**. Every one of these was one line of prose away from looking right.

**`scripts/corpus-verify.sh` — the guard, and the reason the count is not the check.** It replays every row against a running badhttp with that row's own url, method and `request_headers`, and fails on 400/404/405/000. The assertion is deliberately narrow and is **not** "every row returns 2xx": this is a server that misbehaves on purpose, so 401 on `/auth`, 402 on `/402`, 416 on `/range`, 418 on `/status` and **500 on `/flaky/50`** are all correct answers. 400/404/405 mean something else — the row does not address the endpoint it claims to. Paced at ~8 req/s under the zone's 100/10 s, `--globoff` so a braced url is fetched rather than glob-expanded, `--max-time` on streaming rows (curl still reports the status once the head arrives). Wired into smoke as `corpuslive`, skippable with `SKIP_CORPUS_VERIFY=1` while iterating. **Proof it works, and the reason I trust it: run against production BEFORE this deploy it reported exactly the three then-broken rows and exited non-zero.**

**A new trap for the record, and it cost a live 500.** `src/page.js` emits markdown from inside JS template literals, so a backtick in the prose ends the literal. An **unbalanced** one is caught by esbuild at build time — it failed the first deploy loudly. A **balanced pair** is syntactically valid JavaScript: `` `21 `/compress` flavors` `` closes the literal, and `/compress/` then parses as division, so the build succeeds and `/llms.txt` returns 500 `"compress is not defined"` at runtime. The smoke suite caught it (`chk llms` wanted 200 text/markdown, got 500 application/json) and six dependent checks failed with it; fixed, redeployed, and reproduced in isolation to be sure of the mechanism. **Rule: escape every backtick in `page.js` prose as `` \` ``, and never trust a green build for a template literal.**
