**1. The build: `/books` stands on the chain alone (v0.23.0).** The question was how to restore the itemized list without the indexer. Probed 2026-10-09, keyless: no indexer serves Base (Etherscan v2 "Free API access is not supported for this chain"; Basescan a Cloudflare challenge; Routescan "chain not supported" for 8453); no public RPC answers `eth_getLogs` over more than 1,000 blocks (`base.rpc.thirdweb.com` 1,000; `mainnet.base.org` 500 and a per-IP penalty that persists for minutes once tripped; 1rpc.io and nodies 50; blastapi 10; dRPC refuses any width on its free plan; publicnode calls it an archive request), and a month of Base is ~1.3M blocks. What every public RPC does answer is **`eth_getTransactionReceipt`**, batched — so the list is now built the other way round. **The books name every transaction they claim** (each `chain_movements` row and each `revenue` row carries a tx hash: 14 at the start of the session, 15 after this session's self-test); the Worker reads each receipt in one JSON-RPC batch, takes the USDC `Transfer` logs in it that touch the receive address as the rows, and **confirms each book row against the chain** — tx, direction and exact atomic amount — or shows it as unconfirmed, loudly, with the reason. Blockscout never did that: it listed what the chain had and the books labeled it; now the books claim and the chain judges. What the list cannot do is discover a transaction the books do not name, and the page says so in its own paragraph rather than letting the table read as exhaustive: that was always the aggregate identity's job (balance − labeled movements − booked revenue = unbooked, from `balanceOf` on the RPC), and it still is; the session that books an unknown payment finds its hash with the new `scripts/find-transfers.mjs`.
- `src/chain.js`: the Blockscout section replaced. `RECEIPT_RPCS` = `mainnet.base.org` → `base-mainnet.public.blastapi.io` → `base.rpc.thirdweb.com` (each answered a 14-receipt and a 14-header batch keylessly; dRPC allows 3 items per batch, 1rpc.io has pruned blocks before 51,000,000 and this address's first movements are in 50,571,xxx, publicnode and tatum want a token or a paid plan, nodies and meowrpc answered batches with non-JSON). RPCs are tried **in order, item by item**: each is asked only for what the previous ones did not answer, because a public RPC answers a batch item-by-item and may refuse some while serving the rest — the first offline render had five of fourteen block timestamps missing for exactly that reason. **Three outcomes per receipt are kept apart on purpose:** an object (read), a `null` result from an RPC that answered (the tx is unknown — a genuine finding), and an error (the RPC refused this item). A tx that every RPC *refused* makes the whole read incomplete and the view degrades to its error state, which smoke tolerates and says out loud — because a rate limit must never render as "unconfirmed", which on the public books reads as a bookkeeping bug. Zero-value transfers are dropped (forgeable address-poisoning spam; a genuine movement has value > 0). Block headers supply timestamps and are decoration, not evidence: a header the RPCs will not serve leaves the row dated by block number. New cache key `books-chain-receipts` (the old key's records have a different shape) carrying `named_key`, the joined list of named hashes, so a deploy that books a new transaction is never served a list that predates it for longer than one stale read; same 300 s stale-while-revalidate and 3 s cold-colo budget as the balance.
- `src/index.js` `transfersView`: builds the expected rows from the books keyed by `tx:direction` (a row explains one leg, not a whole tx), confirms by exact amount; labels `AMOUNT MISMATCH` (the chain and the book row disagree — the chain is right), `unbooked` (an incoming leg inside a named tx that no row explains), `UNEXPLAINED WITHDRAWAL`, `self-transfer`; publishes `books_rows_named`, `books_rows_confirmed`, `books_rows_unconfirmed[]` (with the receipt read's reason), `amount_mismatch_count`, `matches_balance` (now exact — no truncation caveat, no "indexer lag"), `method`, `discovery` (the sentence about what the list cannot show) and a `reproduce` curl for one receipt that explains how to read the log.
- `src/page.js`: the section is now "Every movement the books name, confirmed on chain"; an unconfirmed-rows alarm; the cross-check sentence states the sum equals the balance when it does ("every unit the address holds is explained by a transaction the books name") and names both possible causes when it does not; `itemizedClean` — the condition for "Every transaction the books name is confirmed on chain below, and those rows sum to the balance" — now requires `matches_balance === true` and zero unconfirmed rows. Footer, `/llms.txt`, `/openapi.json` (description, `/books.json` summary and schema prose) and README no longer say "itemized transfer list from a public Blockscout indexer".
