Controls that are fully RFC-correct: `basic` (RFC 7617; wrong-vs-undecodable credentials distinguished per RFC 9110 §11.4, the body names the decode defect), `bearer` (RFC 6750; the invalid_request 400 / invalid_token 401 / insufficient_scope 403 triple, challenge ON the 403 per §3.1 — deliberately contrasted with `forbidden`'s challenge-less 403), `digest` and `digest-sha256` (RFC 7616: qop="auth" with cnonce+nc REQUIRED, nc exactly 8 hex, legacy no-qop rejected 400, uri= string-compared against the request-target with mismatch → 400 per §3.4.6 — diagnostic body carries uri_param_length only, no-echo invariant — stale=true when the deterministic 5-minute bucket nonce ages out, opaque validated-if-present, MUST-complete Authentication-Info: rspauth + cnonce + nc + qop echo, nextnonce deliberately omitted). Misbehaviors: `none` (401 with NO challenge, a §15.5.2 MUST violation; doubles as the preemptive-auth witness — only unprompted credentials ever succeed), `bare-scheme`, `unknown-scheme` (invented name; Negotiate/NTLM banned family-wide — SSPI clients would answer with real handshake material), `token68` (a token68-form challenge FIRST in the comma-joined list), `multi` (Digest+Basic in one header — what workerd emits anyway: a platform probe showed appended WWW-Authenticate headers coalesce, which killed the planned multi-header flavor), `case`, `quoted` (comma and escaped quotes inside the realm, badhttp-prefixed), `utf8` (accepts BOTH UTF-8 and Latin-1 encodings of agent:sésame, NFC-normalized, reports which — charset is advisory per RFC 7617 §2.1), `always-401`, `accept-any` (truthiness on purpose — models `if (req.headers.authorization)`; reports the scheme only when it names Basic/Bearer/Digest so a bare secret sent as the whole header is never reflected), `forbidden`, `stale` (generation dance in the nonce, stateless: valid-over-g1 → stale=true+g2, valid-over-g2 → 200, wrong password → plain 401 never stale), `proxy` (407 from an origin), `redirect` (302 to /auth/basic — do credentials follow?).
