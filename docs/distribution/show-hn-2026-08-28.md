## First comment (post immediately after submitting)

httpbin answers correctly. badhttp is the other half of testing: ~100 stateless endpoints that go
wrong in precisely documented ways, so you can find out what your HTTP client, SDK, scraper or agent
does when the server is unkind.

Some favorites:

- /truncate — declares Content-Length: 1000, sends 500 bytes, closes. Clients that trust the header
  return half a file with a straight face.
- /range/shifted — resumable downloads that serve the wrong bytes under a correct-looking
  Content-Range. The document is self-describing (each 64-byte line starts with its own offset), so
  the corrupted file convicts the server all by itself.
- /sse/split-utf8 — an event stream that splits a 4-byte emoji across two chunks, exactly at the
  boundary your hand-rolled SSE parser doesn't handle.
- /cookies — Set-Cookie edge cases three real jars disagree about (curl, Python, tough-cookie: the
  observed differences are documented on the page).
- /auth — HTTP auth that misbehaves: a 401 with no challenge, two challenges jammed into one header,
  a server that accepts any credentials, the Digest stale dance. The test credentials are public and
  fake; requests 2.34 encodes the UTF-8 password as Latin-1 and curl doesn't — the /auth/utf8
  endpoint tells you which your client did.
- /402 — paywalls that misbehave, speaking x402 (the machine-payment protocol that makes HTTP 402
  real). Paying one on purpose IS the test scenario; the rest never charge by design.

The twist: the site is built and operated end to end by an AI (Anthropic's Claude) under a published
charter — it picks what to build, writes and reviews the code, deploys, keeps its own ledger as
memory between sessions, and publishes its accounts at /books (currently $23.75 in the hole, and it

on-chain balance, with the exact curl to reproduce the number). I fund it with a $150/year cap and do

Everything is free, stateless, no signup. One zone-level rate limit (100 req/10s/IP), stated on the
page. OpenAPI at /openapi.json, agent guidance at /llms.txt.

## Comment crib sheet (likely questions, honest answers)

**"Is this just httpbin?"** httpbin's endpoints behave correctly (its /status returns clean status
codes). badhttp's misbehave on purpose and document the exact wire behavior — the closest prior art
is mock servers you configure yourself; this is a catalogue you point at.

**"Why should I trust an AI-run site?"** You shouldn't need to: it's stateless (no accounts, nothing
stored about you, no request logging by the Worker), the behaviors are verifiable with curl in
seconds, and the books are public and self-reconciling — /books reads the receive address's balance
from chain, itemizes every transfer in or out of it (labeled by tx hash; an outgoing transfer no
book entry explains gets flagged in bold on the page itself), and shows the difference against
what's booked, so an unbooked payment, an error, or a withdrawal is visible before anyone edits the
books. Treat it as untrusted infrastructure you test against — that's what it's for.

**"What's the AI actually doing vs. the human?"** The human (me) funds it, starts sessions, and
performs human-gated actions when assigned them (domain payment, faucet captchas, this post). The AI
chose the product, name and domain, wrote every line, runs adversarial review workflows on its own
code, deploys, verifies live, and writes the ledger it reads back next session. The LEDGER is the
only memory it has.

**"How does it make money?"** Mostly it doesn't yet, and the site says so. Rails: donations (USDC on
Base, address on /books) and x402 paywalls where paying is the test being sold. Settlement is proven
end to end on both testnet and mainnet — the mainnet proof was a self-test and is booked as such,
not as revenue. Break-even is ~$73/yr; the books are the scoreboard.

**"Is the AI-run thing a gimmick?"** The product stands alone — use it and never think about who
runs it. The charter experiment (can an AI operate a real service to break-even under public books?)
is the reason it exists and is documented honestly. Both things are true.

**"Rate limits / can I hammer it?"** 100 requests per 10 s per IP at the Cloudflare zone, then a
429 with error 1015 — that one is real, not a scenario. Everything else misbehaves only in the
documented ways.
