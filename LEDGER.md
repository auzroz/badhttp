- **`/crosshost`'s three invariants (session 22) — none of them may be relaxed.** (a) **No open redirect, by construction:** no byte a caller sends reaches a `Location`; targets are complete absolute URLs in a frozen table selected by flavor name via `Object.hasOwn`, each checked against `LOCATION_OK` before emission, failing closed to a 500; the one protocol-relative value is admitted by **exact string equality, never by pattern**, because a regex that admits the `//host` shape at all is one mistake from admitting `//evil.example`. (b) **No echo:** nothing that arrives on the wire is reflected — not whole, not truncated, and **deliberately not hashed** (a digest of a weak credential is a cracking target, not a mitigation); the observables are presence, a scheme name only when it is Basic/Bearer/Digest, and a byte length; cookie names only for cookies badhttp minted. (c) **A response without `x-badhttp-version` is not an observation** — it is Cloudflare's rate-limit 429, and recording it as "the credential did not survive" is a false reading. The witness block on `/crosshost` is a **dated capture**; re-run it and move the date rather than letting it stale (`chk chwitness` pins the date).

- **Witness data lives in `/clients.jsonl` and nowhere else (session 23, 2026-09-17).** A family's witness block on its own index (`/crosshost` → `witness`) is DERIVED from the rows — date, counts, roster and every number inside the findings — never hand-written beside them, so the two surfaces cannot disagree; the hand-typed home-page note is pinned to the rows by smoke (`chwitnesspagedate`) instead. A capture is re-run whole, never patched row by row, and its run log is committed beside it so "N retries" is a claim the record supports; every landed row must carry the `x-badhttp-version` the provenance line names or the parser refuses. Explanations of *why* a named client behaves as it does are gated on the computed list they were written for, so a re-capture that moves a list drops the explanation rather than misattributing it. Harnesses live in `scripts/<family>-witness/`, run one at a time against one IP, and send only the family's published fake values.

- **`/clients.jsonl` auth rows name what was CONFIGURED, never what happened (session 25, 2026-09-18).** `mechanism_kind` is a fixed vocabulary of what the harness handed the client for that flavor (`basic-auth`, `basic-header`, `basic-handler`, `digest-handler`, `any-handler`, `bearer-auth`, `bearer-header`, `no-mechanism`), chosen per flavor and never by the client; whether credentials went out first, and how many requests carried them, is read from `hops` (per request: status and header presence, never a value). **Build decision: the family #20 and #21 both recommended — with its premise corrected before a line was written.** Both prior sessions argued for the cross-host redirect credential-boundary family on the grounds that *you cannot test whether an agent framework revalidates each redirect hop from a listener on 127.0.0.1, because the SSRF filter under test rejects it at hop zero.* **That half is true and it is the whole justification.** The other half — the implication that nobody hosts such a fixture — **is not**, and the research found it out: `httpbin.org` redirects to `eu.httpbin.org` (a real subdomain, real DNS, real TLS) and to `httpbingo.org` (a different registrable domain) today, through httpbin's `/redirect-to?url=` **open redirect**, which the maintained reimplementation `go-httpbin` has already closed with an allowlist. **The budget question, answered by measurement rather than by preference.** The open design question was whether a *subdomain* is a real credential boundary or whether the family needed a second registered domain (~$11/yr against $0.01 of lifetime earnings). Reading twelve clients' source and then measuring eight of them live: **a subdomain is a boundary for nearly all of them, and Go net/http is the exception — by documented design.** `shouldCopyHeaderOnRedirect()` forwards Go's sensitive headers when the destination is the initial host *or a subdomain of it*, and the doc comment says so outright. **So the free subdomain is not a compromise, it is the better fixture: a second apex domain would show every client stripping and split nothing.** No domain was bought. `wrangler.jsonc` gained one line; the zone's universal certificate already covered `*.badhttp.dev`; the zone is on the Free plan at $0 and custom domains are not a billed unit (100 per zone; this zone now uses 2).

**Built (v0.17.0): `/crosshost`, nine flavors across two hosts.** `badhttp.dev` and `alt.badhttp.dev`, one Worker. `same-origin` (the control), `to-subdomain` (the flagship), `from-subdomain` (the same boundary reversed — it starts on the alt host), `boomerang` (out and back, ending where it began), `port-change` (`badhttp.dev` → `badhttp.dev:8443`, which Cloudflare serves for this zone under the same certificate), `relative-authority` (a protocol-relative `Location: //alt.badhttp.dev/…`, RFC 3986 §4.2, held as an exact constant), `scheme-upgrade` and `scheme-downgrade` (http↔https on one host; `always_use_https` is off and no HSTS header is sent, so both directions are buildable), and `jar` (host-only, `Domain=`-scoped and `__Host-` cookies planted before crossing). `/crosshost/land` is the oracle, served on both hosts, and reports what arrived.

**Three invariants the family is built on, all of them load-bearing.**
- **No open redirect, by construction.** No byte a caller sends reaches a `Location`. Targets are complete absolute URLs in a frozen `TARGETS` table selected by flavor name via `Object.hasOwn`, and every one is checked against `LOCATION_OK` before it is emitted, failing closed to a 500 rather than sending an unrecognized target. The single protocol-relative value is admitted by **exact string equality**, never by pattern, because a regex that admits the `//host` shape at all is one mistake from admitting `//evil.example`. There is no `?url=`, `?next=` or `?to=`, and smoke asserts that adding all three to a flavor URL changes nothing.
- **No echo, ever.** This family exists to be sent credentials by people testing whether their client leaks them, so some of those will be real ones sent by mistake. Nothing that arrives is reflected — not whole, not truncated, and **deliberately not hashed**, because a digest of a weak credential is a cracking target rather than a mitigation. The observables are presence, a scheme name only when it is Basic/Bearer/Digest (so a bare secret sent as an entire header value never has its first token reflected as a "scheme"), and a byte length. Cookie names are listed only for cookies badhttp itself minted. A credential that is not one of the published fakes gets a warning telling the caller to rotate it.
- **The alt host is a fixture, not a second site.** It serves `/crosshost`, its own `robots.txt` (`Disallow: /`) and `/health`, 404s everything else with a pointer home, and carries `X-Robots-Tag: noindex` on **every** response.
